# 웹 분석 설정과 로컬 검증

안녕재고 웹 분석의 구현과 재현 가능한 검사를 설명한다. 운영 계정·승인 원문과 날짜별 실행 증거는 공개 저장소 밖에서 관리하며 로컬 검사에 필수 의존으로 두지 않는다.

## 변경 위치

- `_config.yml`: 공개 GA4 measurement ID. 관리용 property·stream 식별자는 소스에 기록할 필요가 없다.
- `_includes/web-analytics.html`: 공통 footer에서 사용하는 동의 화면과 설정 버튼.
- `assets/js/analytics.js`: 동의 저장, 태그·이벤트 전송과 철회 처리.
- `privacy/index.html#website-analytics`: 웹 분석 개인정보 안내. 앱의 개인정보 처리와 구분한다.

## 유지할 동작

- HTTPS의 정확한 `hi-inven.com`에서만 분석을 활성화한다. 로컬·미리보기·다른 호스트에서는 Google 태그를 불러오지 않는다.
- 선택 전과 거부 후에는 분석 태그·이벤트를 전송하지 않는다. 사용자는 footer의 웹 분석 설정에서 선택을 바꿀 수 있다.
- 허용 후 태그를 한 번 로드하고 `page_view`를 수동으로 한 번 전송한다. Google 관리 설정에서도 자동 page view·outbound click과의 중복 여부를 별도로 확인한다.
- 설치 클릭은 설정된 App Store 목적지에만 기록한다. 클릭을 실제 설치로 간주하지 않으며 링크 이동을 차단하거나 지연시키지 않는다.
- 페이지 주소는 정적 canonical URL, 유입 주소는 HTTP(S) origin으로 제한한다. 임의 query·hash·이메일·앱 재고를 전송하지 않는다.
- `analytics_debug=1`에서만 debug 표시를 넣고 일반 방문에서는 필드 자체를 생략한다.
- 철회 시 분석을 비활성화하고 해당 설정의 GA 쿠키를 제거한 뒤 다시 로드한다. 다른 탭의 철회와 저장 실패도 처리한다. 이미 전송된 데이터의 소급 삭제와 구분한다.

## 로컬 검사

README의 의존성 준비 후 다음 검사를 실행한다. 분석 검사는 외부 요청 없이 수행한다.

```sh
node --test script/check-analytics.cjs
bundle exec ruby script/check.rb
```

Node 검사는 동의 전·거부·허용·철회, 중복 태그/이벤트, 정확한 설치 링크, 주소 제한, 운영 호스트, debug 분리와 저장 실패를 확인한다.
사이트 검사는 Jekyll 빌드, 정책 JSON, 분석 include·설정값·JS 복사 일치와 내부 지침·문서의 산출물 제외를 확인한다.

## 운영 확인과 기록

Google의 관리 계정·소유권·향상된 측정·필터·DebugView와 보고서 수신은 운영 담당이 승인된 환경에서 별도로 확인한다. HTTP 성공 응답만으로 Google 화면의 수신이나 보고서 집계를 완료했다고 판단하지 않는다.

실제 Google 전송 검사는 운영 데이터에 영향을 줄 수 있으므로 기존 승인 범위에서 필요한 최소 횟수로 수행한다. 이 문서는 신규 전송·계정·권한 변경의 승인이 아니다. 날짜별 승인·관리 식별값·브라우저 로그·화면 원본은 비공개 운영 기록에 보존한다.

이 기능의 2026-10-15 도입·배포 원문과 성공/실패 증거도 비공개 보존소에 원본으로 보존한다. 공개 Git 이력은 다시 쓰지 않는다. 문서 검수와 실제 운영 수신 검증을 구분한다.
